## ⚡ Optimize IMAP Fetching

💡 **What:** Replaced the N+1 `m.fetch` calls inside a loop with a single batch `m.fetch` request, requesting all `ids` concatenated by a comma at once. It also parses the batched output properly to maintain the same ordering.

🎯 **Why:** Fetching emails one by one inside a loop causes `N` network round trips, which is extremely slow, especially when processing multiple emails (e.g. limit=10). By doing a single batch `fetch` call, we bring network latency to `O(1)`.

📊 **Measured Improvement:**
In a simulated local benchmark with a simulated 10ms network delay:
- **Baseline (Old Approach):** 0.2058s for 20 emails
- **Optimized (New Approach):** 0.0111s for 20 emails
- **Improvement:** Around **18.5x faster**, as the new approach scales much better by removing network round trips from the loop.
🎯 **What:** The `execute_shell` function in `tools.py` contained a command injection vulnerability due to the use of `subprocess.run` with `shell=True`.
⚠️ **Risk:** An attacker could exploit this by providing a command with shell metacharacters (e.g., `|`, `;`, `&&`, `$()`) to execute arbitrary shell commands. The existing check using `BLOCKED_COMMANDS` was insufficient because it only matched explicit strings and could easily be bypassed. This could lead to a complete system compromise depending on the user running the agent.
🛡️ **Solution:** Modified the `subprocess.run` call in `execute_shell` to use `shell=False`. The command string is now parsed into a list of arguments using `shlex.split(command)` before being passed to `subprocess.run`. This ensures the arguments are passed directly to the executable, avoiding the shell interpreter entirely and preventing command injection.
