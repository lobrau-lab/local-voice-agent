🎯 **What:** The `execute_python` tool permitted arbitrary code execution by passing user-supplied input unchecked to a `subprocess.run(["python", "-c", ...])`.
⚠️ **Risk:** Exploiting this tool allows arbitrary file system access (e.g., via `os`, `shutil`, `open`), executing system commands (via `subprocess`), reading environment variables, and making outbound network connections. Because an agent has access to it, a compromised state or malicious prompt could easily pivot to arbitrary shell execution.
🛡️ **Solution:** Added a strict AST parser-based `_is_safe_python_code` validation step before executing any code. It statically checks the code's Abstract Syntax Tree (AST) to explicitly forbid dangerous module imports (e.g., `os`, `sys`, `subprocess`), dangerous built-ins (e.g., `eval`, `exec`, `open`, `__import__`, `getattr`), and dangerous attribute accesses (e.g., `__class__`, `__subclasses__`). This ensures `execute_python` can safely be used for basic data processing and calculations while blocking malicious payloads. We added automated tests to verify the sandbox mechanism.
